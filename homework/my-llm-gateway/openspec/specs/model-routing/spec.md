# model-routing Specification

## Purpose

定义模型别名路由行为：公开别名到候选路由（供应商 + 真实模型 ID + 权重）的映射、priority 与加权两种策略、路由失败语义与启动期 fail-fast 校验，确保真实模型 ID 与上游协议细节不向北暴露。

## Requirements

### Requirement: 别名路由表
路由表 SHALL 结构化为「公开别名 → 候选路由列表」，每条路由包含供应商、真实模型 ID 与权重。命中路由后由该供应商的适配器完成请求改写与鉴权注入，结果反向翻译回北向协议；真实模型 ID 与上游协议细节 MUST NOT 出现在北向响应中。

#### Scenario: 别名命中并隐藏真实模型
- **WHEN** 请求携带已配置的公开别名
- **THEN** 请求被路由到对应供应商的真实模型，北向响应的 model 字段只出现公开别名

### Requirement: 路由策略
路由 SHALL 支持两种策略：
- priority：严格按配置顺序尝试候选路由
- 加权轮询：按权重选择本次首选路由，其余路由保留为后备

#### Scenario: priority 按序尝试
- **WHEN** 别名配置为 priority 策略且首选路由重试耗尽失败
- **THEN** 按配置顺序切换到下一条候选路由

#### Scenario: 加权首选与后备保留
- **WHEN** 别名配置为加权轮询策略
- **THEN** 按权重选出本次首选路由，其余路由作为后备可在故障转移时使用

### Requirement: 路由失败语义
未知别名 MUST 返回 404「模型不存在」；别名存在但无健康路由（全部被熔断或禁用）MUST 返回 503。

#### Scenario: 未知别名 404
- **WHEN** 请求携带未配置的模型别名
- **THEN** 返回 404，错误体为统一封装且语义为模型不存在

#### Scenario: 无健康路由 503
- **WHEN** 别名的全部候选路由所属供应商均已熔断或被禁用
- **THEN** 返回 503，错误体为统一封装

### Requirement: 启动期路由配置校验（fail fast）
路由引用了不存在的供应商、或供应商声明了未知的协议类型时，网关 MUST 在启动时直接失败退出，MUST NOT 带病运行。

#### Scenario: 引用未知供应商启动失败（场景 15）
- **WHEN** 配置中某路由引用了供应商表中不存在的供应商
- **THEN** 网关启动失败并退出，报错信息指出违规配置

#### Scenario: 未知协议类型启动失败（场景 15）
- **WHEN** 某供应商声明了不存在的协议类型
- **THEN** 网关启动失败并退出
