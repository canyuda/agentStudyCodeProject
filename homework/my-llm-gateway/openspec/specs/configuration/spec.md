# configuration Specification

## Purpose

定义配置体系行为：YAML 主配置与环境变量展开（`${VAR}` / `${VAR:-默认值}`）、密钥仅经 `.env` 注入且被版本控制忽略、配置文件路径解析与内置示例回退、启动期全量校验失败即退出。

## Requirements

### Requirement: 环境变量展开
YAML 主配置 SHALL 支持 `${VAR}` 与 `${VAR:-默认值}` 两种环境变量展开形式；密钥 MUST 只通过环境变量注入，MUST NOT 硬编码落盘于主配置、代码或配置样例。

#### Scenario: 两种展开形式生效
- **WHEN** 配置中分别使用 `${VAR}`（变量已设置）与 `${VAR:-默认值}`（变量未设置）
- **THEN** 前者展开为变量值，后者展开为默认值

### Requirement: 密钥与 .env
上游供应商 API Key SHALL 写入项目根目录 `.env` 文件，主配置经环境变量引用注入该值；`.gitignore` MUST 忽略 `.env` 与 `.env.*`；代码与配置样例中 MUST NOT 出现真实密钥。

#### Scenario: .env 被版本控制忽略
- **WHEN** 检查 `.gitignore` 规则与仓库状态
- **THEN** `.env` 与 `.env.*` 均被忽略，真实密钥不会进入任何被跟踪文件

### Requirement: 配置面与路径解析
配置 SHALL 覆盖：服务名、网关密钥列表、数据库路径、重试/熔断/限流/结构化修复轮次/流检查点/脱敏的参数、供应商表、模型路由表、价格表。支持通过环境变量指定配置文件路径；未提供配置时 MUST 回退到内置示例配置，保证开箱可跑。

#### Scenario: 未提供配置回退示例
- **WHEN** 不设置配置路径环境变量启动网关
- **THEN** 网关使用内置示例配置正常启动并通过健康检查

#### Scenario: 指定配置路径生效
- **WHEN** 通过环境变量指向自定义配置文件启动
- **THEN** 网关加载该文件而非示例配置

### Requirement: 启动期校验失败即退出
所有配置校验 SHALL 在启动时完成，任一校验失败（含但不限于：YAML 语法错误、必填项缺失、路由引用未知供应商、供应商声明未知协议类型）即退出进程，MUST NOT 带病运行。

#### Scenario: 非法配置启动失败
- **WHEN** 提供语法错误或缺少必填项的配置启动网关
- **THEN** 进程以非零码退出并给出可定位的报错信息
