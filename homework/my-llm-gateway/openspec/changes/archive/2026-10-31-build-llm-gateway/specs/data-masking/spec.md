# Spec Delta

## Purpose

定义可开启/关闭的数据脱敏能力：表驱动的五类敏感信息识别与执行顺序、类型标记 + 序号占位符与请求内映射、非流式与结构化输出的还原、流式跨块还原的尾部缓冲，以及与修复回路、账本、检查点、日志的交互红线。

## ADDED Requirements

### Requirement: 处理流程与开关
配置级总开关 SHALL 默认关闭，通过主配置开启。开启后处理管道顺序 MUST 为：鉴权 → 限流 → 提示词渲染 → 脱敏 → 路由 → 上游供应商；上游响应 → 还原 → 客户端。脱敏对象限调用方提供的内容（消息正文与模板变量值）；网关内置的模板骨架与系统生成的错误文本 MUST NOT 脱敏。

#### Scenario: 默认关闭不脱敏
- **WHEN** 未开启脱敏发起含敏感信息的请求
- **THEN** 内容原样发往上游、原样返回客户端

#### Scenario: 模板变量值同样脱敏
- **WHEN** 开启脱敏且提示词引用的变量值命中敏感规则
- **THEN** 发往上游的渲染结果中该值被替换为占位符

### Requirement: 表驱动规则集
规则集 SHALL 表驱动，每类规则可独立启停、可扩展新规则：
- 邮箱：通用邮箱正则
- 手机号：中国大陆 `1[3-9]` 开头 11 位，前后需是非数字边界
- 身份证：18 位（末位可为 X），加校验码验证
- 银行卡：13–19 位数字，容忍空格分组，加 Luhn 校验
- 密钥：`sk_` / `sk-` 前缀的令牌串

执行顺序 MUST 为更具体/更长的规则优先：密钥 → 银行卡 → 身份证 → 手机号 → 邮箱，避免短规则截断长号码（如手机号是身份证的子串）。用户有意发送的同形字符串（测试样例、代码）也会被脱敏，SHALL 声明为已知可接受行为。

#### Scenario: 五类规则往返（场景 12）
- **WHEN** 开启脱敏，请求中包含五类敏感信息各一例
- **THEN** 发往上游的内容中五类均被替换为占位符；客户端最终收到全部原值

#### Scenario: 校验降低误报
- **WHEN** 内容包含 18 位但校验码非法的数字串、或 13–19 位但 Luhn 校验失败的数字串
- **THEN** 均不被识别为身份证/银行卡，原样保留

#### Scenario: 长短规则顺序
- **WHEN** 一个身份证号内含手机号形态的子串
- **THEN** 整体命中身份证规则，不被手机号规则截断

### Requirement: 占位符与请求内映射
命中后 SHALL 替换为「类型标记 + 序号」形式的占位令牌，需满足：不易被模型改写、不与正常文本冲突、UTF-8 安全、能穿越 SSE 分块传输。同一原值在一次请求内 MUST 始终映射到同一占位符；不同值分配不同占位符。映射表只存在于本次请求的内存作用域，请求结束即丢弃，MUST NOT 写入日志、用量账本或任何持久化存储。

#### Scenario: 同值同占位符
- **WHEN** 同一敏感值在一次请求中出现多次
- **THEN** 每次出现被替换为完全相同的占位符；不同值对应不同占位符

### Requirement: 非流式与结构化还原
非流式响应 SHALL 在返回前对整体文本做还原；JSON 结构化输出中字符串值内的占位符 MUST 被文本级替换覆盖（还原后仍是合法 JSON 且通过 Schema 校验）。

#### Scenario: JSON 内字符串值还原（场景 14）
- **WHEN** 开启脱敏且结构化输出的 JSON 字符串值中含占位符
- **THEN** 客户端收到的 JSON 中该值被还原为原值，且仍合法并通过 Schema 校验

### Requirement: 流式还原的尾部缓冲
占位符可能被 SSE 分块切开：还原器 MUST 维护「待定尾部缓冲」——只有当缓冲内容不可能再构成任何占位符前缀时才下发给客户端，确保跨块占位符完整还原。模型改写/丢失占位符时，未匹配到原值的占位符 MUST 原样保留，MUST NOT 把原值重新发给模型修补。

#### Scenario: 占位符跨 SSE 分块被切开仍还原（场景 13）
- **WHEN** 开启脱敏做流式调用，某占位符恰好被切分在两个相邻 SSE 块
- **THEN** 客户端收到的内容中该占位符被完整还原为原值，无占位符碎片外泄

#### Scenario: 丢失占位符原样保留
- **WHEN** 模型输出中改写或丢弃了某占位符
- **THEN** 未匹配的占位符文本原样下发给客户端，不触发任何向模型回发原值的修补

### Requirement: 与其他模块的交互红线
结构化输出修复回路中，修复指令 MUST 携带脱敏后的模型上轮输出（模型全程只见占位符）；还原只发生在最终面向客户端的响应处。用量账本可记录「脱敏命中数」（仅按类型计数，不记任何内容）。流检查点保存客户端可见文本（即已还原文本）。任何日志 MUST NOT 输出敏感原值或映射表。

#### Scenario: 修复回路全程只见占位符（场景 14）
- **WHEN** 开启脱敏且结构化输出触发修复闭环
- **THEN** 发往模型（含修复轮）的所有内容只含占位符，客户端最终响应中的占位符已还原
